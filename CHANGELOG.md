## Unreleased

- Steering: Fixed `position_indices` during decode and chunked prefill. The absolute start of each forward pass was always 0, so a position in a later prefill chunk was never steered, and position 0 was steered again on every decode step. The start now comes from the request's computed-token count, which does not depend on the attention backend.
- Capture: Added `output_residual_stream_pool` (`capture_pool` on the client). `"last"` returns the last prompt position and `"mean"` the mean over the prompt positions, as one row per layer.
- Capture: Added `output_residual_stream_project` (`capture_project` on the client). The worker returns the projection of every position onto `(N, hidden)` directions and the norm of every position, in float32, in place of the residual. Each distinct direction set goes to the workers once, keyed by its hash, and is released when its last request finishes.
- Capture: A step's captured rows go to the host in one queued copy into pinned memory, pooled rows are summed in one gather, and projections take one matmul per direction set, so the hooks do not wait for the GPU. The offline batch collection finds each request by its external id.
- Capture: The offline batch collection writes each rank's captures into a memfd of the caller, and the caller's tensors are views of it; where the worker cannot open the memfd, each tensor travels as a msgpack extension that vLLM decodes as a view of the received frame. There is no pickle, no client copy and no 4 GiB cap: a 1.2 GB full capture collects in 0.3 s in place of 3 s. The tensors of one call share one host buffer (see README).
- Plugin: Added a CUDA-graph mode. `VLLM_LENS_CAPTURE_LAYERS` and `VLLM_LENS_STEER_LAYERS` keep compilation and CUDA graphs on, and one custom op on each named layer steers and captures inside the graph. Hooks, Q/K capture and layers outside the lists fail with an error.
- Steering: Each request's vectors are summed once into a row table, and each step applies all requests' rows in one gather per layer, in eager mode and under CUDA graphs; a layer with nothing to do in a forward pass returns at once. In eager mode, every `norm_match` vector on a layer is now scaled to the norm of the unsteered stream.
- Offline: `LLM.generate` and `LLM.chat` work on copies of the caller's `SamplingParams`. Before, they removed the steering vectors and hooks from the caller's `extra_args`, so a `SamplingParams` passed to a second call was not steered. The worker state of a call is released also when the call raises.
- Steering: A vector that is a view into a larger tensor is copied before it is pickled for the workers. A row of an `(N, hidden)` matrix pickled the whole matrix.
- Plugin: `register()` attaches a stderr handler to the `vllm_lens` logger when it has none, so the INFO records of the package are no longer dropped. `VLLM_LENS_LOG_LEVEL` sets the level (default `INFO`).

## v1.3.0 (2 October 2026)

- Compatibility: Pin vLLM to the GPU-validated **0.30.0** release, with V1/eager execution. Add CPU regression CI and reproducible Slurm smoke/TP/PP suites; FP32 reference parity retains the 0.01 threshold and BF16 functional checks remain. See `docs/compatibility.md` for exact environments and coverage. (#39, #41)
- Hooks: Fix post-hook replacements on fused residual outputs, including zeroing hooks, while preserving other requests and original tensors. Serving patch failures now include actionable diagnostics; strict compatibility mode fails registration when required integration is missing. (#41)
- Development: Remove private benchmark Git dependencies. Public Hugging Face APIs prefetch data/models, and benchmark launchers accept explicit Apptainer image directories. Align the development lock with CUDA 13.0 and Transformers 5.18.0. (#41)
- Plugin: For fp32 models, `TRITON_F32_DEFAULT` now defaults to `ieee` so vLLM's Triton attention kernel computes in true fp32 instead of TF32 (which leaked ~1e-3 relative error per layer into activations; vLLM already defaults its linears to true fp32). An explicit `TRITON_F32_DEFAULT` still wins.
- Activations: Added an opt-in **binary transport** for activation payloads over the HTTP API (`activations_transport="binary"` in `vllm_xargs` / the client). Instead of base64-inlining the (already zstd-compressed) tensors in the JSON body — which inflates ~33% and forces the whole blob to be materialized and parsed in one piece on both ends — the raw bytes are parked in a bounded, TTL'd, process-local store under an unguessable handle, and the client fetches them from `GET /v1/activations/{handle}` as `application/octet-stream`. Default responses are byte-identical (base64); `decode_activations` and `VLLMLensClient` handle both transports transparently. The store is bounded by `VLLM_LENS_ACT_MAX_BYTES` (default 8 GiB) and `VLLM_LENS_ACT_TTL_S` (default 300 s), and is process-local (pin fetches to the producing replica in multi-replica deployments). (#31)
- Activations: Added per-request attention Q/K capture (`extra_args={"output_qk": ...}`, client `capture_qk=`) plus `vllm_lens.attention.attention_patterns` / `compute_attention_weights`, which reconstruct true attention matrices offline from the captured post-RoPE Q/K and per-layer kernel parameters (GQA, sliding window, logit soft-cap, ALiBi, sinks). Works offline/online, sync/async, under chunked prefill, and under TP/PP (every TP rank captures its head shard; merged head-dim/layer-dim). MLA models are rejected with a clear error. (#34)
- Plugin: Decoder-layer discovery now uses vLLM's `static_forward_context` attention-layer registry instead of hardcoded attribute paths (`model.model.layers`, …), so capture, steering, and hooks work on any decoder architecture vLLM can serve — including MLA (DeepSeek/GLM-5), hybrid (Mamba/linear-attention), and multimodal layouts. Only known decoder mixers (`Attention`, `MLAAttention`, `MambaBase`) are treated as layer markers; the discovered map is checked against the config's `num_hidden_layers` and discovery **fails loudly** (`LayerDiscoveryError`) on any mismatch rather than falling back to a guess. New `VLLM_LENS_LAYER_PATH` env var (a `get_submodule` path template, e.g. `model.layers.{i}`) overrides discovery for layouts the registry can't resolve. (#33)
- Examples: Added **R-lens** — an LRP variant of the Jacobian-lens fit (`jacobian_lens_fit.py --rules lrp`; rules in `examples/r_lens_rules.py`: LN-rule on residual-stream RMSNorms, identity + half rules on the gated MLP), making early-layer readouts markedly more faithful. The rules are pure stop-gradients, so the forward pass and the lens `.pt` format are unchanged and the existing readout + chat visualizer consume R-lenses as-is; `provenance["rules"]` records which backward was used. Dense models only for now (MoE fails fast at startup). CPU-only unit tests cover the rules in `examples/tests/test_r_lens_rules.py`.

## v1.2.0 (17 July 2026)

- Hooks: Added a generic, Garçon-style hook system — run arbitrary Python functions per-request and per-layer to capture data (via `ctx.saved`) and/or modify hidden states (by returning a tensor). Supports per-request hooks (`apply_hooks` in `extra_args`), persistent register-once hooks (`register_hooks` / `collect_hook_results` / `clear_hooks`), and pre-hooks (run before the layer forward pass). Exposed over HTTP at `/v1/hooks/*` and through a `VLLMLensClient`; `ctx.get_parameter()` gathers parameters across tensor- and pipeline-parallel ranks. (#3)
- Hooks: Added `POST /v1/hooks/clear_results` (`client.clear_hook_results()`) — drain accumulated persistent-hook results while keeping the hooks registered, so long-lived clients can bound accumulation without re-uploading hook state. (#25)
- Steering: Fixed `norm_match` on fused-residual architectures (Qwen, Gemma, Llama, …). It now scales the steering vector to the full residual stream rather than the MLP-delta half, so the injected magnitude equals `‖residual‖ · scale` as intended. **Behavior change:** existing `norm_match=True` steering becomes correspondingly stronger. (#7, #15)
- Performance: On the offline `LLM.generate` path, a batch's captured activations are now fetched in a single RPC instead of one per request. (#6)

- Examples: Moved examples to a top-level `examples/` directory and added causal-tracing, logit-lens, deception-probe, and emotion-concepts examples. (#4, #11)
- Examples: Added a Jacobian-lens / J-space example — fit a per-model average Jacobian `J_l = E[∂h_final/∂h_l]` offline (HuggingFace backward pass), then read it out live on vLLM-captured residuals to see what the model is "disposed to say" at each layer. (#19)

- Examples: Added a live J-space chat visualizer — chat with a served model in a generated HTML page where every token is hoverable, showing the streaming top-k Jacobian-lens readout across the captured layers. (#25)
